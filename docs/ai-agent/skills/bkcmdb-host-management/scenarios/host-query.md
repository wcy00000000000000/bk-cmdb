# 场景：host_query（按 IP / 主机 ID / 固资号 查主机）

按主机标识符在蓝鲸配置平台（bk-cmdb）中定位主机：查它属于哪个业务、集群、模块、拓扑路径，并给出主机的完整属性。能力通过直接调用 bk-cmdb 的只读查询工具实现（工具所在 MCP server 注册名以环境为准，按工具名定位）。

## 适用场景

本场景按用户意图分三种查询视图（标识符可为 IP / 主机 ID / 固资号，下文以 IP 举例，其余标识符同理）：

- **查询（默认）→ `概览`**：按标识符查主机的**关键属性**，四类整理字段（基础 / 拓扑归属 / 地域 / 规格，含业务归属与拓扑路径、负责人、地域、可用区、CPU 核数、内存量、磁盘、规格机型等）。默认就给这个，不多给。支持单个 / 批量。
- **查询拓扑 → `拓扑`**：定位主机**所属拓扑**（业务/集群/模块/拓扑路径），或者**统计该拓扑节点下的主机数 / IP 数量**等盘点信息（如「这台机所在集群/模块共挂了多少主机」）。
- **查询详情 → `详情`**：把各工具返回的**全部原始字段**逐一列出（domain-terms 已映射的给中文名，未映射的直接用接口字段名）。

判定意图后走对应视图：未特别说明默认 `概览`；问「在哪个拓扑/集群/模块下、下面有多少机器」走 `拓扑`；问「全部字段/接口字段/原始字段」走 `详情`。`概览` 与 `详情` 共用主机查询主流程，`拓扑` 在归属解析基础上额外做拓扑节点下主机盘点。

## 不适用场景

- 写操作：主机转移、集群/模块创建、属性修改、拓扑变更（本 skill 不做）。
- 集群/模块资源汇总、容量统计、集群变更历史。
- 编造业务 ID、业务名、固资号、拓扑路径、负责人，或臆测是否有访问权限（无权限须按 `blocked_by_permission` 说明，不能说成无数据）。bk-cmdb 没返回就如实说没有，不要猜。

## 支持的标识符（入口）

主机定位入口支持三类标识符，定位后的归属解析、视图呈现完全一致；三类入口仅「过滤字段」不同，`page` 必填、`fields` 处理、后续步骤 2–5 完全一致。

| 标识符 | CMDB 字段 | 识别特征 |
|---|---|---|
| 内网 IP | `bk_host_innerip` | 形如 `127.0.0.1` 的合法 IP（默认入口） |
| 主机 ID | `bk_host_id` | CMDB 内部主机 ID，纯数字、非 IP（如 `10001`） |
| 固资号 | `bk_asset_id` | 固定资产编号，**无固定格式**（可含字母/数字/符号） |

- **标识符判定**：合法 IP → `bk_host_innerip`。**固资号无固定格式**，不能凭前缀/字母判定：
  - 用户明确说是「固资号 / 资产号 / asset_id」→ 直接按 `bk_asset_id` 查；明确说是「主机 ID / host_id」→ 按 `bk_host_id` 查。
  - 未指明类型时，纯数字既可能是主机 ID 也可能是固资号，非 IP 字符串也可能是固资号 → 用 `OR` 同时匹配候选字段（如 `bk_host_id` / `bk_asset_id`）一次查全，再以实际命中字段为准向用户说明；仍无法判定才澄清。

具体过滤写法（单值 / 多值 / `OR` 组合）见下「查询流程」步骤 1。

## 查询流程

三种视图共用「步骤 1–4」这条主链做 IP 定位与归属解析；`拓扑` 视图在此基础上追加「步骤 5」做拓扑节点下主机盘点。所有工具均为 bk-cmdb 的工具。

1. **按标识符查主机**（无需业务权限，单/多目标一次查）
   `open_list_hosts_without_biz`，用 `host_property_filter` 按标识符对应字段过滤（见上「支持的标识符」表，按内网 IP / 主机 ID / 固资号 三选一或 `OR` 组合）：
   - 单值：`{"field":"<识别字段>","operator":"equal","value":<值>}`（IP / 固资号为字符串，主机 ID 为整数）
   - 多值：同字段 `operator:"in"`, `value:[...]`；混合标识符用 `OR` 组合多条规则
   - `page` 必填；**显式传 `fields`，按视图取所需字段，不要省略 `fields` 拉全量**：
     - `概览`：传 domain-terms 的「`概览` 推荐 `fields`」固定字段集。
     - `拓扑`：只取归属相关最小集 `["bk_host_id", "bk_host_innerip"]`（集群/模块归属由步骤 2 获取）。
     - `详情`：用户明确要「全部原始字段」，此时才不传 `fields` 取全量。
   - 拿到每条记录的 `bk_host_id` 及主机属性（用固资号/主机 ID 入口时，结果里也会带 `bk_host_innerip`，呈现时一并给出）。

2. **查业务/集群/模块归属**
   `open_find_host_biz_relations`，入参 `bk_host_id`（数组）→ 返回 `bk_biz_id` / `bk_set_id` / `bk_module_id`。

3. **集群 / 模块 ID → 名称**
   - 集群名：`open_find_set_batch`（`bk_ids`=set_id 列表，`fields` 含 `bk_set_name`）。
   - 模块名：`open_find_module_batch`（`bk_ids`=module_id 列表，`fields` 含 `bk_module_name`）。
   - 业务名（可选）：
     - **先判主机池**：调用 internal MCP 的 `get_resource_pool_biz`，取得调用方所在租户的主机池 `bk_biz_id`。主机 `bk_biz_id` 与之相等时按主机池处理（显示「主机池」、跳过本步骤后续解析），规则见 `domain-terms.md`「主机池识别」。不要从 Prompt 读取主机池业务 ID。
     - 否则用 `open_search_business` 按 `bk_biz_id` 查 `bk_biz_name`；**返回业务名与权限无关——普通业务即使无业务访问权限也能拿到名字**。

4. **拼装拓扑路径**：`业务名 / 集群名 / 模块名`（业务名缺失时用 `业务ID:<id> / 集群名 / 模块名`）。

5. **（仅 `拓扑` 视图）统计拓扑节点下的主机 / IP 数量**
   用步骤 2 拿到的 `bk_biz_id` + `bk_set_id` / `bk_module_id`，调用 `open_list_biz_hosts` 统计节点下主机：
   - `open_list_biz_hosts`（`bk_set_ids`=集群 ID 列表 或 `bk_module_ids`=模块 ID 列表，`page` 必填）→ 返回 `count`（节点下主机数）+ `info`（主机列表，可据此数 IP）。
   - ⚠️ 该工具**需目标业务的 `find_business_resource`（业务访问）权限**，无权限时返回 `code 9900403 / 没有操作的权限`，按 `blocked_by_permission` 如实说明、不要伪造数量、不要无脑重试。
   - 通常按集群、模块两个层级各统计一次；多 IP 落在多个不同节点时分别统计并去重（同一节点只统计一次）。

> ⚠️ 步骤 2、3 的归属/名称解析工具不需要业务访问权限，更稳，优先用；步骤 5 的盘点统计才需要业务访问权限。不要用 `open_list_biz_hosts` 做归属解析：它同样需要 `find_business_resource` 权限，对未授权业务会触发 `blocked_by_permission`。

各工具入参/出参与调用样例见 `../references/host-query-api-reference.md`；字段映射、术语与「不可编造字段」见 `../references/domain-terms.md`。

## 状态处理

每次查询都明确归类并忠实呈现，禁止把部分结果说成完整结果：

- **found** — 已找到（计数口径）。面向用户的措辞统一用「已登记」（如「该主机在 bk-cmdb 中已登记」）。返回约定字段；缺失字段标「-」并说明 bk-cmdb 未提供。
- **not_found** — `count=0` 或某 IP 无记录。明确提示该 IP「检索为 0 / 未找到」，不返回任何虚构拓扑。
- **partial** — 批量场景部分 IP 已找到、或部分字段缺失。给出「共 N 个 IP，已找到 M，未找到 N-M」汇总，逐条标注。
- **blocked_by_permission** — 工具返回 `没有操作的权限` / `code 9900403` / HTTP 401/403。说明缺失的权限（如业务访问）和恢复动作，**不要伪造数据，也不要无脑重试**。

分类规则与症状见 `../references/troubleshooting.md`。

## 输出格式

用 Markdown 呈现，排版（标题、分组、表格还是列表、字段顺序、详略）自行决定，怎么清晰怎么来。核心约束（忠实、缺失标「-」、批量汇总）必须遵守。

一份完整响应通常应覆盖以下**要素**（这是内容清单，不是固定模板，可按场景增删合并）：

- **状态**：`found` / `not_found` / `partial` / `blocked_by_permission` 之一（定义见上「状态处理」），让用户一眼看出查询结果。
- **主机事实**：按需呈现基础（主机 ID / 内网 IP / 固资号 / 负责人主备）、拓扑归属（业务名+ID / 集群名 / 模块名 / 拓扑路径）、地域（地域 / 可用区 / 管控区 ID）、规格（CPU / 内存 / 磁盘 / 机型）；`概览`给四类整理字段，`拓扑`只给归属+盘点（见下），`详情`给全部接口字段（见下）。
- **缺失与说明**：缺了什么、为什么缺（权限 / 未纳管 / 未返回）。只写面向用户的事实，不要交代实现细节（用了哪个接口、接口可不可靠、是否需要业务权限等）。
- **CMDB 记录更新时间**：已找到且工具返回 `last_time` / `bk_updated_at` 时附（细节见下），未返回则省略。

批量多 IP 时，建议一行一主机并附已找到/未找到汇总。

### 各视图输出要点

- **`概览`（默认）**：四类整理字段，缺失标「-」。不展开接口原始字段，不做拓扑盘点。
- **`拓扑`**：先给该 IP 的拓扑归属与路径（业务名+ID / 集群名 / 模块名 / 拓扑路径），再给盘点——「所在集群下主机数 / 所在模块下主机数 / IP 数量」等（来自步骤 5 的 `count` 与主机列表）。数量必须来自工具返回，**不可估算或臆造**；无业务访问权限时按 `blocked_by_permission` 说明拿不到盘点数据，归属路径仍可正常给出（步骤 2、3 不需权限）。多 IP 时逐 IP 给归属，再按落在的不同拓扑节点汇总数量（同节点只统计一次）。
- **`详情`**：见下「详情视图」。

### 详情视图（用户要求展示全部接口字段时）

当用户要求「展示全部字段 / 接口字段 / 原始字段」时，按工具分组，把每个工具 `data` 里返回的**所有字段**逐一列出，不做裁剪：

- 建表三列：`接口字段`（接口原始 key，用反引号）｜ `含义`（domain-terms 已映射的给中文名；未映射的此列填「—」，不臆造含义）｜ `值`。
- 分组：`open_list_hosts_without_biz`（主机字段）、`open_find_host_biz_relations`（归属 ID）、`open_find_set_batch` / `open_find_module_batch` / `open_search_business`（拓扑名称）各一张表；末尾附拼装出的拓扑路径。
- 取值忠实：空字符串与 `null` 一律按「-」呈现；多值（如 `operator`）原样保留；不补、不猜、不丢字段。
- 该视图仍遵守核心约束（忠实、缺失标「-」），只是详略上把字段全展开；CMDB 更新时间（`last_time` / `bk_updated_at`）作为普通字段在表中体现即可。

### CMDB 记录更新时间（可选）

已找到主机时，若 `open_list_hosts_without_biz` 返回 `last_time` 或 `bk_updated_at`，可在末尾附 CMDB 记录更新时间（原样保留时区，不标注来源字段名）；未返回则省略。批量多 IP 时，每台已找到的主机各自附（若返回）。
