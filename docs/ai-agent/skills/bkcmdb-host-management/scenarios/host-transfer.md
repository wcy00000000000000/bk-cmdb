# 场景：主机拓扑/模块转移

实现蓝鲸 CMDB 主机拓扑/模块转移功能，支持单主机或多主机批量操作。当用户需要进行主机转移、模块迁移、主机腾挪、拓扑转移、主机分配、主机上交（归还空闲机池或资源池）、主机回收等操作时使用。

## 核心工作流

查询工具入参/出参与调用样例见 `../references/host-query-api-reference.md`；主机转移工具入参/出参与调用样例见 `../references/transfer-host-api-reference.md`；字段映射、术语与「不可编造字段」见 `../references/domain-terms.md`。

主机池属于调用方所在租户。主机池业务 ID 通过隐藏 MCP 的 `get_resource_pool_biz` 获取，不从 Prompt 或用户输入读取。规则见 `domain-terms.md`「主机池识别」。

所有转移操作必须严格遵循：**校验 → 预览 → 二次确认 → 执行 → 验证**。
支持**单主机或多主机批量操作**。用户可一次指定多个主机（多个 IP、多个固资号、或混合输入），系统将批量查询、批量预览、批量转移。

根据主机来源分为两种场景：

### 场景 A：资源池主机转移（主机当前在资源池中）

用户输入：主机信息 + 目标业务信息 + 目标集群和模块信息
1. 解析用户输入，提取全部主机标识列表
2. 使用 `open_list_resource_pool_hosts` 批量查询资源池中的主机
3. 查询目标业务和目标模块信息
4. 生成转移预览
5. 等待用户二次确认
6. 调用 `open_transfer_resourcehost_to_idlemodule` 将主机分配至目标业务空闲机
7. 如目标模块非空闲机，再调用 `open_transfer_host_module` 转移到目标模块
8. 批量验证转移结果

### 场景 B：非资源池主机转移（主机当前在某业务下）

用户输入：源业务信息 + 主机信息 + 目标业务信息 + 目标集群和模块信息
1. 解析用户输入，提取全部主机标识列表和源业务信息
2. 使用 `open_list_biz_hosts` 批量查询业务下的主机
3. 使用 `open_find_host_biz_relations` 获取主机当前拓扑位置
4. 查询目标业务和目标模块信息
5. 生成转移预览
6. 等待用户二次确认
7. 根据场景调用对应转移工具执行
8. 批量验证转移结果

### 场景判断规则

- 用户明确说源业务为"资源池"或"主机池"，如转移资源池下的主机：场景 A
- 用户指定了源业务名称/ID，如转移 xxx 业务下的主机：场景 B
- 用户未明确来源：先询问主机当前所在位置（资源池 or 某业务下）

---

## Step 1: 解析输入 & 查询主机信息

### 解析主机标识列表

从用户输入中提取所有主机标识，支持以下格式：
- 多个内网 IP：`10.0.0.1, 10.0.0.2, 10.0.0.3` 或 `10.0.0.1 10.0.0.2 10.0.0.3`（逗号/空格/换行分隔）
- 多个固资号：`SVR-001, SVR-002, SVR-003`
- 多个主机 ID：`12345, 67890`
- 混合输入：`10.0.0.1, SVR-002, 12345`（IP 和固资号和 ID 混合）

如果用户输入的主机数量超过100，则按照100台主机一批分批执行以下步骤

### 场景 A：查询资源池主机

调用 `open_list_resource_pool_hosts`，通过 `host_property_filter` 匹配用户输入的 ID、内网 IP 或固资号，获取每台主机的 ID、内网 IP 和固资号

### 场景 B：查询业务下主机

1. 查询源业务：通过 `open_search_business` 按 ID 或名称查找，获取源业务的 ID 和名称
2. 批量查询主机：调用 `open_list_biz_hosts`，通过 `host_property_filter` 匹配用户输入的 ID、内网 IP 或固资号，获取每台主机的 ID、内网 IP 和固资号
3. 查询拓扑路径：调用 `open_find_host_biz_relations` 传入 `bk_host_id` 数组，获取每台主机的 `bk_biz_id`、`bk_set_id`、`bk_module_id`
4. 聚合所有主机拓扑的 `bk_set_id` 并去重，调用 `open_find_set_batch` 根据集群 ID 查询集群名称
5. 聚合所有主机拓扑的 `bk_module_id` 并去重，调用 `open_find_module_batch` 根据模块 ID 查询模块名称

### 通用注意事项

- 查询完成后，比对返回结果与输入列表，找出未匹配的主机标识并提示用户

---

## Step 2: 查询并校验目标业务和模块

1. 使用 `open_search_business` 按业务 ID 或者业务名称查询目标业务的 ID 和名称
2. 使用 `open_search_set` 按集群 ID 或者集群名称查询目标集群的 ID 和名称
3. 使用 `open_search_module` 按模块 ID 或模块名称查询目标模块的 ID 和名称

### 校验规则

- 目标业务/集群/模块不存在：提示用户重新确认参数
- 源模块与目标模块相同：过滤掉该主机，提示"无需转移"
- 用户未指定目标业务：询问用户是否使用源业务作为目标业务，或者指定其他目标业务

---

## Step 3: 生成转移预览

组装可读预览文本，包含：
- 转移类型、主机数量、目标业务、目标集群、目标模块
- 每台主机的详细信息表格，包括：ID、IP、固资号、源集群/模块信息（仅场景 B 需要展示该信息）
- 风险提示
- 确认提问

> 如果只有 1 台主机，可简化为单行摘要格式。
> 如果主机属于多个模块，按以下示例格式展示所有源拓扑信息：
| ID | 内网 IP | 固资编号 | 源拓扑 |
|------|------|------|------|
| 123 | 127.0.0.1 | ABC0001 | 集群1/模块1;集群2/模块2 |

---

## Step 4: 等待用户确认

**必须**等待用户明确回复"确认/是/yes/执行"后才执行转移。 未确认则不调用任何写接口。
对于批量操作，确认时需明确告知用户主机总数。

---

## Step 5: 执行转移

### 场景 A：资源池主机转移执行

1. 使用 `open_transfer_resourcehost_to_idlemodule` 从资源池转移到目标业务空闲机 ->
2. 如果目标模块不是空闲机，使用 `open_transfer_host_module` 从目标业务空闲机转移到最终目标模块

### 场景 B：非资源池主机转移执行

根据具体操作类型选择对应工具执行转移操作，必须按照 [transfer-host-api-reference](../references/transfer-host-api-reference.md) 中的参数进行调用：
- 转移至业务内普通模块（非空闲机/故障机/待回收模块）：`open_transfer_host_module`
- 转移至空闲机模块：`open_transfer_host_to_idlemodule`
- 转移至故障机模块：`open_transfer_host_to_faultmodule`
- 转移至待回收模块：`open_transfer_host_to_recyclemodule`
- 转移至资源池：
    1. 如果源模块不是空闲机模块需要先使用 `open_transfer_host_to_idlemodule` 将主机转到空闲机
    2. 如果需要转移到非空闲机的资源池目录，需要用户指定资源池目录的 ID，否则默认转移到资源池的空闲机目录中
    3. 使用 `open_transfer_host_to_resourcemodule` 将主机从空闲机转移到资源池
- 转移至其他业务：
    1. 如果源模块不是空闲机模块需要先使用 `open_transfer_host_to_idlemodule` 将主机转到空闲机
    2. 如果目标模块不是空闲机池集群下的模块，需要先使用 `open_get_biz_internal_module` 获取目标业务的空闲机模块 ID 作为中转的目标模块 ID，否则直接使用用户指定的目标模块 ID 进行跨业务转移操作
    3. 使用 `open_transfer_host_across_biz` 将主机从空闲机模块转移到目标业务的空闲机池集群下的模块
    4. 如果目标模块不是空闲机池集群下的模块，调用 `open_transfer_host_module` 将主机从目标业务的空闲机模块转移到目标模块

### 分组转移策略

当用户一次提供的多台主机属于不同场景时，需按场景分组执行：
1. 将主机按来源分为场景 A 组（资源池）和场景 B 组（业务）
2. 场景 B 组内若存在不同源业务或不同转移类型，继续细分
3. 如果同组内有多台机器需要转移，一次性传入这些主机 ID 进行批量转移，如果需要转移的主机数大于100，则按照100一批继续细分。
4. 逐组执行，前一组完成后再执行下一组
5. 记录每组的执行结果

---

## Step 6: 批量验证转移结果

转移执行后，自动验证：

1. 调用 `open_find_host_biz_relations` 传入全部 host_id 列表查询当前归属
2. 逐台对比预期目标模块，汇总验证结论（成功/失败/总数）
3. 如有失败主机，输出失败原因并建议到 bk-cmdb 页面核实实际状态

---

## 注意事项

- 批量查询时使用 `in` 操作符批量匹配，而非为每个资源单独查询
- `page.limit` 设置为需要查询的资源数量
- 如果需要查询的数据量大于100，则按照100一批分批查询
- 如果查询数据量超过单页上限，需分页查询直到获取所有结果

---

## 安全约束

1. **写操作必须二次确认**：未经用户确认不得调用任何转移工具
2. **不保证幂等**：明确告知用户重复执行可能导致非预期结果
3. **预览不含敏感信息**：不在预览中暴露凭证或密钥
4. **批量上限保护**：单次批量转移最多 100 台主机，超出时自动分批
5. **部分失败处理**：批量转移中如遇部分失败，需逐台报告结果，不可静默忽略
6. **源模块过滤**：已在目标模块的主机自动从转移列表中剔除，避免无意义操作
