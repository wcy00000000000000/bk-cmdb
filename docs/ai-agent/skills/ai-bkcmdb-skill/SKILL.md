# bk-cmdb 蓝鲸配置平台技能

bk-cmdb 是蓝鲸配置平台的主机资产管理与主机拓扑管理技能工具，提供主机的业务归属、集群/模块、拓扑路径与资产配置属性等当前信息。

本技能按场景组织：先判定用户意图所属**场景**，再读对应 `scenarios/` 下的场景执行说明执行；跨场景的工具契约、术语、排障放在 `references/`，按需读。

## 一、核心约束

所有场景都必须遵守：

- **忠实**：只呈现工具返回的事实；字段缺失标「-」，不补、不猜、不用历史记忆值。
- **禁止编造**：业务 ID/名、固资号、拓扑路径、负责人、主机是否纳管一律以工具返回为准；是否有业务访问权限也以工具返回判定，无权限按 `blocked_by_permission` 如实说明、不能说成无数据；CMDB 更新时间须来自 `last_time` / `bk_updated_at`。bk-cmdb 没返回就如实说没有。
- **批量汇总**：多目标必须给已找到/未找到统计，不能只列已找到的。
- **多值字段**：`operator` / `bk_bak_operator` 等可能是逗号分隔的多人，原样保留。
- **写操作先预览后确认**：涉及创建/修改/删除拓扑的写工具，必须先输出预览并获得用户明确确认（如「确认创建」）后再执行。
- **写结果需验证**：写接口返回成功不等于最终成功；必须通过查询工具验证落库结果。验证未命中时按失败/不一致处理，不能臆断成功。
- **server 名不硬编码**：工具由「提供 bk-cmdb 工具（如 `open_list_hosts_without_biz`）的 MCP server」承载，其注册名以环境为准（例如某环境为 `bk-cmdb-prod-mcp` 和 `bk-cmdb-prod-internal`），按工具名定位实际 server，不要把任何具体 server 名当作固定值。
- **多租户**：租户以调用方身份所在租户为准，不从用户话术猜测，也不跨租户查询。同一轮调用里的业务、主机等资源都属于该租户。

## 二、鉴权

鉴权由运行环境默认打通，直接调用 bk-cmdb 对应 MCP server 的工具即可。调用方租户由运行环境带入，skill 不读取、不传递、不展示租户 ID、token、bk_ticket 或调用细节；调用失败时按工具返回值原样反馈。

## 三、场景路由

- **host_query**（只读）：给内网 IP / 主机 ID（`bk_host_id`）/ 固资号（`bk_asset_id`）问主机归属 / 集群 / 模块 / 拓扑路径 / 配置属性 → 读 `scenarios/host-query.md`。
- **topology_create**（写）：创建集群 / 创建模块 / 按模板创建拓扑（不含主机分配、主机转移）→ 读 `scenarios/topology-create.md`。
- **host_transfer**（读写）：进行主机转移、模块迁移、主机腾挪、拓扑转移、主机分配、主机上交、主机回收等操作 → 读 `scenarios/host-transfer.md`。

判定场景后，**只读取对应的那一个场景文件**再执行。无法归类时向用户澄清意图，不要臆测。
