# bk-cmdb 查询排障与状态分类

按症状把每次查询结果归类到一个状态，忠实呈现，禁止伪造数据。

## not_found（检索为 0）

症状：

- `open_list_hosts_without_biz` 返回 `data.count = 0`；
- 批量查询中某些 IP 在结果里没有对应记录。

处理：明确提示该 IP「检索为 0 / 未找到（可能未纳管）」。**不要**返回任何虚构的业务/集群/拓扑。批量场景给「共 N 个 IP，已找到 M，未找到 N-M」并逐条列出未找到 IP。

## blocked_by_permission（无权限）

症状：

- 返回 `没有操作的权限` / `code: 9900403`，`permission` 字段给出所需 IAM（如 `find_business_resource` 业务访问）；
- HTTP 401 / 403。

处理：说明缺失的权限（哪个业务、哪个动作）与恢复动作（申请对应业务的访问权限）。**不要无脑重试，不要把无权限说成无数据。**


## partial（部分已找到 / 部分字段缺失）

症状：

- 批量 IP 部分已找到；
- 已找到主机的某些字段为 `null` / 空（如 `bk_cpu` / `bk_mem` / `bk_disk` 在部分非 CVM 主机上为空）。

处理：不要把 partial 当 found。逐条标注哪些字段「bk-cmdb 未提供」，统计已找到/未找到数量，保留所有 caveat。

## transport_failure（传输/调用失败）

症状：工具调用超时、报错、返回非预期结构。

处理：归类为传输失败，先核对参数格式（`path_param` 与 `body_param` 是否都按 schema 提供、`page` 是否必填项齐全），修正后重试一次；仍失败则如实报告，不要编造结果。

## parse_auth_attribute_fail（解析授权属性失败）

症状：

- 接口返回 `no matched rules`；
- 接口返回错误码 1199045

处理：检查路径是否正确，包括路径参数格式是否正确

- 对于查询接口，检查正确后重试一次，如果还是失败，则报告错误，不要编造结果
- 对于写接口，检查正确后重新预览并等待用户确认

## 批量与限流

- 单次按 IP 批量上限以 MCP/CMDB 实际限制为准，超出时拆分批次。
- `bk_ids`（集群/模块批量查）单次最多 500 个。
